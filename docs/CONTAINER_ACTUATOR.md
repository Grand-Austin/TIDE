## Original reference

The pinned MSS commit is `ce0b40ed101411fc4eebd064b35c5a96916106ad`.
`pipeline.validate_container` checks the source hashes before executing the
original MATLAB code under GNU Octave. It compares seven derivative cases, two
20-second trajectories and a 600-second sustained-rudder trial using identical
RK4 clocks. The stored fixture contains executed Octave results, not Python
outputs. Source authors are Trygve Lauvdal and Thor I. Fossen; the MSS MIT license
is retained in `data/vessels/s175/MSS-LICENSE.txt`.

```sh
uv run python -m pipeline.validate_container --output data/runs/container-comparison
uv run python -m pytest tests/test_container.py tests/test_actuators.py
```

This comparison requires the pinned MSS source files under `data/raw/mss`, or a
matching checkout supplied with `--mss-root`. The JSON fixture supports tests
without a MATLAB/Octave installation.

On 30 October 2026, the executed comparison had zero derivative difference,
maximum short-trajectory absolute difference `1.42e-14`, and maximum 600-second
absolute difference `2.27e-13` (the arrays mix SI state units). The new
runtime actuator-load differences also match forces recovered from original
Octave accelerations: relative L2 difference `3.03e-15`. This independently
checks SI force/moment scaling without relying on the Python force helper. The original
trial starts at 7 m/s and 70 RPM, commands 0.1 rad rudder, and turns 215.54 degrees
in 600 seconds. This is a numerical reproduction, not real-ship accuracy or an
IMO compliance result.

## Runtime integration

Select `"actuator_model": "son_nomoto"` in scenario settings, or pass
`--actuator-model son_nomoto` to `python -m game.simulation`. This intermediate
mode remains available for comparison. The frozen
Menorca reference and callers without this setting retain `teaching` mode.
Existing scene JSON remains a recording of the former settings.

The new runtime retains S175's prepared **M, MA, D and G**, full rigid-body and
added-mass Coriolis terms, ITTC resistance and cross-flow drag. No Son–Nomoto
hull derivatives, masses or restoring terms are added. The current convention
remains the pinned hull model's yaw-only current transform.

The heading PID computes a moment request and converts it to a rudder order
using local rudder effectiveness, including the neutral-rudder moment from
sway/yaw inflow. The speed PI converts a thrust request to ahead RPM. Both
integrators stop winding up at actuator saturation; the heading integral still
operates only near the ordered heading. Hull, actual rudder and actual shaft
states advance together in RK4. Snapshots preserve these states and orders;
samples expose actual/ordered rudder degrees and shaft RPM.

New scene exports include the motion algorithm, settings and seed in `motion`
metadata. Older scene files have no such provenance and are not regenerated by
this change.

The source constraints are ±10 degrees commanded rudder, 5 degrees/s rudder
rate and 160 RPM maximum ahead shaft order, with original first-order servo
equations. `max_yaw_moment_nm` and `max_thrust_n` apply only to `teaching` mode.
There is no additional fixed force cap or invented reverse-thrust brake.
The runtime algorithm identifier is `s175_son_nomoto_actuator_v1`; the legacy
identifier stays unchanged. The old constant-force replay diagnostic rejects
this mode because actuator forces vary across RK4 stages.

## Applicability and measured limitation

The source rudder area (33.0376 m²), propeller diameter (6.533 m), interaction
coefficients and effective lever arms are reused as assumptions about this
175 m hull. The two source loading conditions differ: the original manoeuvring
model uses 8.5 m mean draft and 0.3 m GM; the S175 data uses 9.5 m draft and
0.996 m transverse GM. Actuator terms are evaluated about the runtime CG using
the source's effective arms; this is not a measured refit to the design loading.

Algebraically cancelling advance-ratio divisions permits straight-ahead limits
at zero RPM or zero speed. These are explicit extensions of the original
positive-speed/RPM model. Astern flow, reverse RPM and zero-speed pure yaw remain
unsupported and produce a model-limit stop. No astern or strong-wave actuator
calibration is claimed.

The source rudder-inflow polynomial contains `1/U²` terms. A runtime numerical
envelope `abs(r)*L/U <= 1.5` rejects the extreme low-speed/high-yaw extrapolation
instead of silently producing multi-giganewton-metre loads. This bounds the
normalized input and covers the reference cases (up to about 1.27); it is an
explicit engineering restriction, not an experimentally established vessel
limit. Outside it, the runtime returns `model_limit` at the last accepted state.
Extending low-speed operation requires a validated inflow model, not a force clamp.

`pipeline.validate_maneuvering` moved out of the repository on 2026-10-31 and stays in the local `archive/pipeline/` directory.

```sh
uv run python -m pipeline.validate_maneuvering --seconds 600
```

In calm water at 5 m/s, the combined model starts at about 44.38 RPM. A 10-degree
rudder initially produces 15.92 MN m yaw moment. Holding the initial RPM and
10-degree rudder for 600 s turns ±16.53 degrees, with final yaw rate ±1.65
degrees/min and speed 4.85 m/s. A 90-degree heading order with speed feedback
turns 17.33 degrees in 600 s, ending near 5 m/s and 1.76 degrees/min. The left
and right trials are symmetric. These runs do not complete a 90/180-degree
turn and do not establish a turning diameter.

A matched 600-second 90-degree order at 5 m/s, with the same 0.08 rad/s PID
frequency and 0.5-degree/s reference limit, turns 27.42 degrees in legacy
teaching mode (final 2.77 degrees/min), versus 17.33 degrees with physical
actuators (1.76 degrees/min). Thus actuator fidelity improves, but turning speed
does not. Both runs retain identical S175 hull matrices and have no wind/waves.

An independent pi test compared heading-PID natural frequencies 0.02, 0.04 and
0.08 rad/s for a 10-degree order at 5 m/s over 600 seconds:

| Frequency (rad/s) | Maximum overshoot | Final heading error |
|---|---:|---:|
| 0.02 | 0.00° | +2.03° |
| 0.04 | 3.04° | −3.04° |
| 0.08 | 0.89° | −0.05° |

The Biscay settings retain 0.08 rad/s based on this bounded comparison. No
additional gain increase is justified by the hard-over turning result. The
reference model's rate is a command-shaping limit, not achieved vessel yaw rate.
Independent 60-second runs of all four historical scenarios completed with
finite state and bounded rudder/RPM. Those checks are not full mission passes.

Consequently **the physically bounded actuator integration does not resolve
the slow-turning issue while this equivalent hull model is retained**. Increasing
PID gains cannot overcome sustained rudder saturation. The next modelling
decision is how to reconcile low-frequency manoeuvring derivatives with S175
seakeeping hydrodynamics without duplicating inertia, damping or roll restoring.
Do not reduce a single damping coefficient or enlarge rudder limits to force a
mission pass.

Scenario budgets remain unchanged. Existing validation reports are invalid for
the new configurations. Full strategy validation and regeneration of replays
must follow an accepted manoeuvring model; no report checksum was rewritten.
