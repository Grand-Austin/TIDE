# Data contracts

The pipeline and the web app exchange data only through the JSON documents below. Announce any format change to the team first, and update this file in the same change.

## Conventions

- **Time**: store every timestamp as an ISO 8601 **UTC** string, e.g. `"2019-08-14T06:00:00Z"`. Copernicus Marine data is already in UTC. The UI converts to local time for display (Balearic Islands: UTC+2 in summer, UTC+1 in winter).
- **Coordinates**: `[lon, lat]` in decimal degrees.
- **Units**: wave height m, period s, wave direction is where waves come *from* (degrees true), current direction is where the current flows *to* (degrees true), speed kn, distance nm.
- **Route keys**: `A`, `B`, `C`, with the same meaning in every case.

## 1. Case file — `web/public/cases/<id>.json`

Generated by `pipeline/`, read-only for the web app.

```json
{
  "id": "c07",
  "date": "2019-08-14",
  "title": "Before the north wind",
  "goal": "beam_seas",
  "key_evidence": "wave_dir",
  "vessel": { "speed_kn": 6.0 },
  "limits": {
    "beam_hs": 1.5,
    "max_hs": 2.5,
    "arrive_by": "2019-08-14T18:30:00Z",
    "source": "Citation for the thresholds (standard or textbook, page)"
  },
  "routes": {
    "A": { "name": "Direct crossing", "points": [[3.14, 39.84], [3.83, 40.00]], "nm": 33.2 }
  },
  "grid": {
    "lon": [3.0, 3.05],
    "lat": [39.7, 39.75],
    "times": ["2019-08-14T04:00:00Z"],
    "layers": {
      "hs":        { "unit": "m",    "values": [[[0.7]]] },
      "wave_dir":  { "unit": "deg",  "values": [[[5]]] },
      "period":    { "unit": "s",    "values": [[[5.2]]] },
      "current_u": { "unit": "m/s",  "values": [[[0.0]]] },
      "current_v": { "unit": "m/s",  "values": [[[0.0]]] },
      "wind":      { "unit": "kn",   "values": [[[8]]] },
      "sst":       { "unit": "degC", "values": [[[26.1]]] }
    }
  },
  "forecast_grid": null,
  "sims": {
    "2019-08-14T05:00:00Z": {
      "A": {
        "arrival": "2019-08-14T10:54:00Z",
        "beam_hours": 0.0,
        "over_hours": 0.0,
        "max_hs": 1.1,
        "late": false,
        "safe": true,
        "track": [{ "t": "2019-08-14T05:00:00Z", "lon": 3.14, "lat": 39.84, "hs": 0.7, "category": "beam", "bad": false }]
      }
    }
  },
  "flips": [
    { "at": "2019-08-14T05:00:00Z", "from": "A", "to": "C", "reason": "beam_hours" },
    { "at": "2019-08-14T12:00:00Z", "from": "C", "to": null, "reason": "late" }
  ],
  "copernicus_products": ["<product id>", "<dataset id>"]
}
```

Notes:

- `grid.layers.*.values` is indexed `[time][lat][lon]`. Crop to a small box around the routes to keep files small.
- `forecast_grid`: if the forecast actually issued on that day is available, store it here in the same shape as `grid`. Otherwise set it to `null`; the investigation step then shows `grid` data up to the departure time only, and `docs/METHODS.md` must say so.
- `sims` is keyed by departure time, every 30 minutes is recommended. Each entry must contain all three routes.
- `flips[].to` is `null` when no route is safe from that time on. `reason` is one of `beam_hours` | `over_hours` | `late` | `slower`: why `from` stopped being the best choice. It is `null` when `from` is `null`.
- `goal` takes a value from the learning goals table below. `key_evidence` uses a `grid.layers` key, with `current_u`/`current_v` written as `current`.

## 2. Decision record

Created by the web app when a student submits a decision. Sent to the analysis engine and to `/api/log`.

```json
{
  "session": "random anonymous id",
  "case": "c07",
  "opened": ["hs", "wind", "sst"],
  "route": "A",
  "departure": "2019-08-14T06:00:00Z",
  "reasons": ["hs", "shortest"],
  "note": "Waves were low, so I took the shortest route",
  "submitted_at": "2026-10-30T10:12:00Z"
}
```

`reasons` values: `hs` | `wave_dir` | `period` | `current` | `wind` | `shortest` | `arrival`. No names, emails or other personal data are collected.

## 3. Analysis result

Computed in the browser by `analysis.js` from the case file and the decision record. **This is the only input to the AI coach**; the coach never sees raw sea-state data.

```json
{
  "case": "c07",
  "safe": false,
  "facts": { "max_hs": 1.9, "beam_hours": 1.3, "arrival": "2019-08-14T11:55:00Z" },
  "missed_key_evidence": "wave_dir",
  "better_option": { "route": "C", "arrival": "2019-08-14T12:35:00Z" },
  "last_safe_departure_for_choice": "2019-08-14T05:00:00Z",
  "weak_goal": "beam_seas",
  "next_case": "c12",
  "student_reasons": ["hs", "shortest"],
  "student_note": "Waves were low, so I took the shortest route"
}
```

`better_option` is `null` when the student already chose the best option. `last_safe_departure_for_choice` is `null` when the chosen route is unsafe all day.

## 4. Coach response — `POST /api/coach`

The request body is the analysis result above. The response:

```json
{ "feedback": "…", "numbers_used": ["1.9", "1.3", "05:00"], "source": "ai" }
```

`source` is `"ai"` or `"template"`. The server checks that every number and time in `feedback` appears in the request body. On a mismatch or a timeout it returns the template text with `source` set to `"template"`.

## 5. Candidate days — `data/candidates.json`

Written by `pipeline/mine.py`, read by `pipeline/export_cases.py`. Pipeline-internal; the web app does not read it.

```json
{
  "generated_by": "pipeline/mine.py",
  "datasets": ["cmems_mod_med_wav_my_4.2km_PT1H-i"],
  "default_limits": { "beam_hs": 1.5, "max_hs": 2.5, "arrive_by": 19.0, "beam_from": 60.0 },
  "combinations": 15,
  "candidates": [
    {
      "date": "2026-09-09",
      "kind": "route",
      "robust_route": 13,
      "robust_any": 15,
      "flips": [{ "at": "2026-09-09T06:00:00Z", "from": "A", "to": "C", "reason": "beam_hours" }],
      "suggested_goal": "beam_seas",
      "max_hs": 4.25,
      "peak_wind": { "kn": 25.0, "from": 30, "at": "2026-09-09T15:00:00Z" }
    }
  ],
  "deadline_only": []
}
```

Notes:

- A **sea-state flip** is a flip whose `reason` is not `late`. Days whose only flips come from the arrival deadline are not candidates; at the default limits they are listed in `deadline_only`.
- `kind`: `route` if the default limits give a sea-state flip from one route to another; `go_no_go` if the default limits only give flips to or from "no safe route"; `other_settings` if the day flips only under other threshold settings or head/beam boundaries.
- `robust_route` and `robust_any`: in how many of the `combinations` (threshold settings × head/beam boundaries, `docs/METHODS.md`) the day has a route-to-route sea-state flip, and any sea-state flip.
- `flips` are at the default limits, in the case-file format. `default_limits.arrive_by` is in hours UTC on the case day.
- Candidates are sorted by `kind`, then `robust_route` and `robust_any`, highest first.

## Learning goals

| Key | Goal | Evidence |
|---|---|---|
| `wind_vs_swell` | Tell wind sea from swell | `period` |
| `beam_seas` | Relate wave direction to heading | `wave_dir` |
| `current_time` | Account for current in passage time | `current` |
| `time_window` | Recognise the departure window | decision map |
